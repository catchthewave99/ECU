# 04 - Stage 1 validation and verification plan (SIL + bench)

Stage 1 answers: *does the Uno, running this firmware, do what the software
design says?* It has two halves that share one set of limits:

* **SIL** - the flashable ELF executed in simavr, stimulated and measured by
  software. Automated, deterministic, runs in about 90 s.
* **Bench** - the same ELF on real hardware with the wiring in
  `docs/08-wiring-chart.md`, observed through LEDs and telemetry. Confirms the
  physical build; it does not attempt precision timing, which is Stage 2's job.

Limits: `tests/limits.env`. Requirements: `docs/03-requirements.md`.
Traceability: `docs/06-traceability-matrix.md`.

## 1. SIL configuration

| Item | Value |
| --- | --- |
| Firmware | `build/uno_baseline/uno_baseline.ino.elf`, built by the suite itself |
| Emulator | simavr, `atmega328p`, 16.000 MHz exactly |
| Stimulus | ADC values injected per channel in mV; crank edges generated by the firmware's own simulator, driven by an `R<rpm>` command over the emulated UART |
| D13 -> D2 and D12 -> D3 | virtual jumpers implemented as PORTB write callbacks, so the SIL and bench signal paths are identical |
| Measurement | `tests/sil/sil_runner` timestamps D4 and D9 transitions from the emulated clock |
| Default stimulus | MAT 3400 mV, CHT 2500 mV, MAP 2500 mV, lambda 2295 mV, pot 512 mV |

Run:

```bash
tests/sil/run_sil_suite.sh                 # arduino-cli must be on PATH
tests/sil/sil_runner build/uno_baseline/uno_baseline.ino.elf --rpm 2000 --ms 6000 --cht-mv 4000
```

The runner reports `n`, `min`, `mean`, `median`, `max` per measurement, so a
single case gives you a distribution rather than one number.

## 2. SIL test cases

Because the emulator's clock is exact, a SIL failure is a firmware failure. That
is the property that makes the later SIL/HIL comparison meaningful.

| Case | Verifies | Stimulus | Acceptance |
| --- | --- | --- | --- |
| TC-SIL-00 | pin map matches firmware | - | all 16 pins in `docs/08-wiring-chart.md` section 8 agree with the sketch constants |
| TC-SIL-01 | REQ-STATE-040, REQ-SPD-023 | no crank, 3 s | 0 injections, `state` 0, `RPM` 0 |
| TC-SIL-02 | REQ-STATE-041/042, REQ-SPD-020/021 | 1200 rpm, 4 s | `state` 1 within `STATE_SETTLE_MS`; `RPM` in [`RPM_1200_MIN`, `RPM_1200_MAX`] |
| TC-SIL-03 | REQ-SENS-011, REQ-FUEL-026/027 | 2000 rpm, CHT 4000 mV then 3300 mV | median pulse in [`PULSE_81C_MIN`, `PULSE_81C_MAX`] then [`PULSE_22C_MIN`, `PULSE_22C_MAX`] |
| TC-SIL-04 | REQ-SPD-020, stimulus fidelity | 800, 2000, 4400 rpm, 8 s each | generated speed within `STIMULUS_SPEED_TOL_PCT`; reported within `ECU_SPEED_TOL_PCT` |
| TC-SIL-05 | REQ-FUEL-032 | 2000 rpm, 30 deg | injector rise to TDC in [`PHASE_2000RPM_MIN`, `PHASE_2000RPM_MAX`] |
| TC-SIL-06 | REQ-SAFE-050 | 6000 rpm, 8 s | D9 asserted, final level high |
| TC-SIL-07 | REQ-FUEL-025/029 | 2000 rpm, 6 s | max pulse <= `PULSE_ABS_MAX_US`; pulse count in [`PULSE_COUNT_MIN`, `PULSE_COUNT_MAX`] |
| TC-SIL-08 | REQ-FUEL-028 | 2000 rpm, 1.2 s window | median pulse in [`PULSE_ENRICH_MIN`, `PULSE_ENRICH_MAX`], `state` 2 |

Latest run: all 20 checks pass. Artefacts land in `build/sil-results/`, one log
per case plus `compile.log` with the flash/SRAM figures.

### Why these eight

They are the minimum set that covers every path from an input to an output:
crank in -> speed (04), speed + CHT -> pulse width (03), state -> enrichment
(08), lambda -> trim (03 indirectly), crank in -> injector phase (05), speed ->
protection (06), and the two boundary behaviours that are not "normal running"
(01, 07). Anything else is telemetry formatting.

## 3. Bench test cases (hardware, no NI yet)

Prerequisite: `docs/08-wiring-chart.md` group A wired and the bring-up steps
passed. Record every result in the log sheet in section 5.

| Case | Group | Method | Acceptance |
| --- | --- | --- | --- |
| TC-BENCH-01 | A | power up, observe telemetry with no crank | `state` 0, `RPM` 0, LED1 dark; note the measured 5 V rail |
| TC-BENCH-02 | A | send `R1200` | `state` 2 then 1 within 2 s, `RPM` 1150 - 1250, LED1 dimly lit |
| TC-BENCH-03 | A | set CHT pot to 4.00 V then 3.30 V (measure at the pin) | `pulse_us` about 2800 then about 3400; `CHT` column about 81 then about 22 degC |
| TC-BENCH-04 | A | send `R0` | `state` 0 within 1 s, LED1 dark, `inj_skipped` unchanged |
| TC-BENCH-05 | B | sweep each analog pot across its range | each telemetry column tracks monotonically, no channel crosstalk |
| TC-BENCH-06 | C | walk the states with `R0`, `R1200`, `R6000` | LED2/4/5 follow the state, LED6 lights above 4000 rpm |
| TC-BENCH-07 | C | sweep the throttle pot | LED3 brightness follows demand, `TPS` column 0 - 100 % |
| TC-BENCH-08 | A | unplug the D12 -> D3 jumper while cranking | injection stops, `state` stays 1 while TDC continues, `RPM` still reported - and note this against O-REQ-2, which does not say what *should* happen |
| TC-BENCH-09 | D | fit the power stage, repeat TC-BENCH-03 | pulse widths unchanged within the TC-03 band; shunt shows current in step with LED1 |

TC-BENCH-08 is deliberately an unspecified case. Run it and record the observed
behaviour; that record is the input to closing O-REQ-2.

## 4. What Stage 1 cannot conclude

* Absolute timing accuracy. The bench measures the Uno with the Uno's own clock,
  so a clock error is invisible (gap G5). Only Stage 2 can measure it.
* Pulse-width accuracy better than "the table value appeared in telemetry".
  Telemetry reports the *commanded* value, not the pin.
* Anything about electrical behaviour: rise times, drive strength, loading,
  noise margin.
* Repeatability, until a case has been run n >= 30 times.

Those four are exactly the Stage 2 scope, and stating them here is what keeps the
Stage 1 report honest.
